## P1 实现与入口

### URL 编解码及兼容

`src/lib/share-params.ts` 提供纯函数解析和序列化，`share-utils.ts` 的 `generateShareUrl` 使用同一序列化入口，既有复制链接和图片二维码继续共用该 URL。

- 经纬度必须为完整有限十进制数，WGS-84 范围为经度 ±180、纬度 ±90；缺失、重复参数和非法坐标停止恢复，界面提供手动选点及定位入口。
- 预设地标同时匹配名称、城市和坐标；同名不同坐标按自定义起点处理，继续遵守原有每日配额和缓存规则。
- 有效方式恢复；非法方式回退驾车并显示原因。缺失方式沿用驾车默认值。
- 固定支持 15 / 30 / 60 分钟。显式携带其他范围的历史或非法链接显示调整说明，按固定三档重新计算；缺失 range 使用当前三档默认值。
- 名称、城市限制长度并拒绝控制字符，异常文本采用默认名称并提示；地点 ID 限定为 1–128 位字母、数字、下划线及连字符，非法编号仅放弃地点选择。
- 分享链接表达重新计算条件，图片表达生成时刻；界面明确说明这两类内容。

### 一次性恢复与请求生命周期

`useShareParams` 保存抵达时的参数快照；`ShareVisitInitializer` 使用可取消调度，在 StrictMode 的 setup / cleanup / setup 后初始化一次。已消费标记不随网络、429、空 features 或配额失败重置。

`IsochroneApp` 的 `handleRestoreShare` 同时供初次恢复和用户显式重看调用。它取消旧请求与定位、清理选点模式，将三档范围写入草稿并提交分享条件。请求仍使用现有 request manager 和 runId 守卫，分享不绕过本地配额。

分享接收端停用原有全站地标后台预加载，避免接收恢复之外的大量请求影响限流判断。失败只显示手动重试或替代入口；错误和空数据区域的“重试”均接回分享恢复函数，保留目标地点。

### 地点及接收者界面

恢复成功后通过同一个 `queryInterestPoints` 几何查询查找稳定地点 ID，设置既有 `selectedPOIId`。地图标记、清单及详情卡沿用原有唯一选择状态，地图复用现有坐标转换和 panInside 路径。

地点已移除或落在新范围之外时，显示解释，保留可用探索。清单处理异常时，保留目标 ID 供现有地点查询重试解析。存在参数或地点提示时，编辑面板保持展开。

结果工具栏显示“分享的探索”，提供“探索我的附近”。面板提供说明、当前分享条件、重新加载分享或返回原分享、手动选点。定位只在点击后启动，定位失败保留原结果和恢复入口；定位开始即取消在途分享请求，避免晚响应覆盖新探索。

### 文案事实来源

本轮仅新增产品操作与状态说明，依据本地 `parseShareParams`、`handleRestoreShare`、`requestGeolocation`、`queryInterestPoints` 和现有图片 payload 行为编写。沿用现有 slate / emerald 配色、圆角与面板样式。参考 public-copy 的能力查证规则；错误解释遵照本工单明确验收要求保留。

## 用户验收顺序

1. 运行 `npm run dev`，从当前有效结果选一个地点，复制链接，在新会话打开。检查起点、方式、三档范围、地点高亮和详情一致，首次引导未遮挡结果，定位未自动触发。
2. 将链接 `range` 改为 `30,60`、`poi` 改为不存在的编号，以及将 `lat` 改为 `NaN`，分别检查说明和替代入口。
3. 模拟请求失败后等待，检查无分享请求自动循环，点击重试后仅恢复原分享条件。检查自定义配额耗尽时的提示与手动选预设入口。
4. 点击“探索我的附近”，拒绝定位后返回原分享或手动选点；允许定位后生成自己的探索，再点击“返回原分享”。
5. 手机扫描分享图片二维码，重复有效地点及定位流程。该项需真实设备及可访问服务。
