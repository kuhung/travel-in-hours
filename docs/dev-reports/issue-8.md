## 1. 目标与背景

在原有实现中，结果展示与信息架构存在以下严重断点：
1. **字符串耦合导致数据断裂**：`IsochroneApp` 曾使用 `getInterestPointsByCity(landmark.city)` 筛选 POI。地图选点（`city: '自定义位置'`）和浏览器定位（`city: '我的位置'`）即便位于上海市中心，也会直接丢失全部 POI 列表；且未消费 #6 的空间覆盖状态评估引擎。
2. **条件截断与移动端隐身**：结果工具栏直接使用 `landmark.name.slice(0, 4)` 截断起点，且文字在移动端视口下被 `hidden sm:flex` 彻底隐藏；工具栏未展示固定 15/30/60 分钟范围与匹配地点数，用户无法在小屏下确认当前结果条件。
3. **打开编辑丢失结果上下文**：当用户点击“修改”展开控制面板时，结果工具栏完全消失，面板内仅有草稿输入框；用户无法对比当前地图展示的 committed 结果与草稿差异，极易造成混淆。
4. **空态空白且误导用户**：`POIListPanel` 曾设定 `if (totalPOIs === 0) return null;`。一旦出发点超出收录范围（`uncovered`）或在范围内暂无收录点（`covered-empty`），面板直接蒸发，空白的地图让用户误以为“该区域在现实生活中没有任何地点/生活设施”。
5. **假拖拽条与不可折叠**：基线中移动端清单固定占据 45vh，顶部灰色细条仅为装饰性无行为元素（无任何拖拽或点击逻辑）；清单缺乏明确的收起/展开按钮，遮挡地图操作。
6. **地图 fitBounds 忽视布局遮挡**：地图 `fitBounds` 硬编码固定对称 `[50, 50]` padding，未考虑桌面端 320px 左侧清单面板和移动端底部面板的实际占位，导致等时圈核心区域和选中标记经常被面板长期遮挡；且状态变化或容器调整易导致反复自动 fit，强行打断用户的拖拽与缩放；动态 import 缺乏版本守卫。
7. **圈层文案混淆单点时间**：图例标为“15/30/60分钟”，列表标为“15/30/60分钟内可达”，未表达最小圈层互斥含义（15分钟内、15–30分钟、30–60分钟），误导用户认为圈层内任意地点均能在该精确时间内到达。

本工单彻底重构结果信息架构（IA），将 #6 的 `queryInterestPoints` 接入生产 UI，建立稳定透明的条件摘要、多态诚实空态、最小互斥圈层表达、自适应视口避让与可折叠清单布局，并为后续 #9（目的地详情与外部导航）预留稳定 POI ID 选择契约。

## 2. 变更前后对照 (Before & After)

| 维度 | 修改前 (Before) | 修改后 (After) |
|---|---|---|
| **POI 检索源** | `getInterestPointsByCity(landmark.city)`，按字符串匹配，选点与定位全丢失 | 接入 #6 唯一 `queryInterestPoints`，严格基于 `committed` 真实等时圈几何做空间匹配 |
| **草稿与结果隔离** | 修改控制面板可能导致展示混淆 | 地图、清单、图例严格只读 `committed` 快照；打开编辑时显式展示“当前查看的结果”卡片与“草稿已修改待更新”提示 |
| **起点条件摘要** | `landmark.name.slice(0, 4)` 截断，移动端隐藏 | 稳定展示起点全名（不截断字符）、出行方式、15/30/60m、示例标签与匹配数，手机/桌面均完整可查 |
| **清单空态处理** | `totalPOIs === 0` 时组件直接 `return null` 空白，无空态说明 | 独立区分 `uncovered`、`covered-empty`、`partial` 与数据异常，提供改条件/看示例出口；数据异常重试仅执行纯函数重算，绝不发起外部网络请求、不消费草稿、不扣配额 |
| **圈层时间语义** | “15分钟内”、“30分钟内”、“60分钟内”重复混淆 | 最小互斥圈层：“15分钟内预估可达”、“15–30分钟预估可达”、“30–60分钟预估可达”，明确“预估圈层，非单点精确时间” |
| **移动端清单操作** | 基线固定 45vh 假拖拽指示条（无点击与拖动手势事件），不可收起 | 统一为 48vh 并替换为明确的“收起清单”与“查看地点清单”药丸按钮；折叠与展开不丢失任何探索结果与选中态 |
| **地图视口 Padding** | 对称固定 `[50, 50]` padding，左侧/底部面板遮挡等时圈 | `calculateMapPadding` 纯函数按桌面清单（320px）、面板及移动端 48vh 动态避让，预留 70% 视口保护安全压缩 |
| **地图手势防打断** | 任意 effect 重新执行触发 `fitBounds` 重置用户缩放；异步回调无版本守卫 | 绑定 `committedTimestamp` 仅新结果生成时适配一次；递增版本守卫确保最新快照胜出；`ResizeObserver` 仅 `invalidateSize()` 绝不重复 fitBounds |
| **POI 选中接口 (#9)** | 仅有 `highlightedPOI`（局部 index），无稳定 ID 选择通道 | 预留 `selectedPOIId` 稳定字符串契约与 `onSelectPOI` 统一回调，地图标记与列表项点击双向接通，不展示工程占位文字 |
| **估算模型披露** | 宣传文案易产生实时交通误解 | 如实披露 500m 网格中心对齐与出行方式折扣（驾车 80%、骑行 70%、步行 60%），不承诺实时路况 |

## 4. 架构与接口契约说明

### 4.1 数据流架构：单向消费 Committed 状态

```
                +---------------------------------------+
                |     CommittedSnapshot (只读展示态)     |
                |  landmark / profile / range / isochrones  |
                +---------------------------------------+
                                   |
                                   v
             [queryInterestPoints(committedSnapshot)]
                                   |
                                   v
    +-------------------------------------------------------------+
    |                     POIQueryResult                          |
    |  status: 'matched' | 'covered-empty' | 'uncovered' | 'partial'|
    |  poiByLayer (带最小互斥圈层)                                   |
    |  allPOIs (带 stable id, GCJ-02 position, index)             |
    +-------------------------------------------------------------+
               /                     |                    \
              v                      v                     v
    [ResultToolbar]            [POIListPanel]        [IsochroneMap]
(稳定起点全名/方式/状态)     (多态空态/互斥分组/折叠)  (视口避让/Marker点击)
```

### 4.2 稳定 POI ID 与详情容器契约（为 #9 预留）

- **单一事实来源**：POI 选择使用 `InterestPoint.id`（例如 `'shanghai-yuyuan'`、`'shanghai-the-bund'`）作为稳定身份标示，而非易受排序变动的 `index`。
- **选择接口**：`onSelectPOI: (poiId: string | null) => void`，在 `IsochroneApp`、`IsochroneMap` 与 `POIListPanel` 之间完全对齐；点击地图气泡 Marker 或点击列表 POI 卡片均调用同一回调。
- **用户端状态呈现**：
  - 选中地点时在清单底部呈现该地点真实名称与描述，不包含暴露给用户的工程开发占位词汇；
  - **边界遵守**：本工单仅打通 ID 选择状态与 UI 回调通道，未接入外部导航或详情重构，不越界进入 #9 范围。

### 4.3 地图视口策略 (Map Viewport Strategy)

- **动态 Padding 计算 (`calculateMapPadding`)**：
  - 桌面端展开清单时：`paddingTopLeft: [344, 80]`，让出左侧 320px 宽度；
  - 桌面端展开编辑面板时：`paddingBottomRight: [344, 48]`，让出右侧 320px 宽度；
  - 移动端展开清单时：`paddingBottomRight: [16, Math.round(containerHeight * 0.48) + 16]`，让出底部 48vh Sheet；
  - 移动端折叠清单时：`paddingBottomRight: [16, 56]`，避让底部悬浮药丸；
  - **极限视口保护**：水平与垂直 padding 之和严格限制在总容器尺寸的 70% 以内，若超出则等比缩小，防止负面积或视口翻转。
- **用户手势保护**：
  - 记录 `lastFittedTimestampRef` 与 `fitRunIdRef`，仅当新的 `committedSnapshot` 产生（`timestamp` 更新）时执行一次 `fitBounds`；
  - 面板切换、清单收展、草稿编辑均不更新 `committedSnapshot.timestamp`，绝对不重置用户的手动拖动和缩放；
  - `ResizeObserver` 仅在 DOM 尺寸变化时触发 `map.invalidateSize()`，保障瓦片充满容器而不移动中心。

## 6. 用户手动核验步骤 (User Manual Verification Steps)

建议用户在本地启动开发环境后按以下步骤验证：

1. **终端自动化测试核验**：
   ```bash
   npm test
   ```
   *预期结果*：42 项测试全部通过（含 9 项 Issue #8 定向测试）。

2. **启动本地开发服务**：
   ```bash
   npm run dev
   ```
   使用浏览器（建议分别使用桌面视口与移动端仿真模式）访问 `http://localhost:3000`。

3. **核验步骤 1：上海示例与完整条件摘要**
   - 点击“先看上海示例”，系统生成宜山路地铁站等时圈与热点清单；
   - 检查右上角工具栏：完整展示“宜山路地铁站”、“驾车”、“15/30/60m”、“示例”标签与地点匹配数；起点全名无 4 字符截断；
   - 界面展示的匹配数与地图上的编号标记数、清单列表项总数完全一致；
   - 切换至移动端尺寸（iPhone 14 / 390px 宽度）：工具栏依然清晰展示起点名与条件，无信息丢失。

4. **核验步骤 2：打开编辑面板与结果上下文保留**
   - 点击工具栏“修改”按钮，控制面板展开；
   - 检查面板顶部：出现“当前地图展示的结果”卡片，清晰标注起点、驾车与地点匹配数；
   - 切换出行方式为“步行”或在输入框选择其他城市，但不要点击生成；
   - 检查面板：出现黄色“草稿已修改，待点击‘更新’生效”提示栏，点击“恢复原条件”即可复原；地图与清单结果在编辑期间完全保持不变。

5. **核验步骤 3：多态空态与操作出口**
   - 在控制面板中选择真实预设地标“杭州 - 杭州东站”，点击“查看可达范围”；
   - 等时圈生成后，检查左侧清单面板：
     - 面板未消失（不为空白）；
     - 显示“超出当前收录范围”卡片，诚实说明目前仅精选收录上海地点，提示“这并不代表附近没有现实生活设施”；
     - 提供“先看上海示例”与“修改出发点”按钮，点击“先看上海示例”可顺畅切回上海。

6. **核验步骤 4：移动端清单收起与展开**
   - 在移动端视口下，观察底部清单：顶部操作栏提供明确的“收起清单”按钮；
   - 点击“收起清单”，面板收起，底部展示“查看地点清单”悬浮药丸；
   - 在地图上自由缩放、拖拽平移，确认地图视野不被反复强行重置；
   - 点击悬浮药丸，清单重新展开，数据与先前一致，无重新加载或闪烁。

7. **核验步骤 5：最小互斥圈层与地点选中**
   - 观察右下角图例与清单分组：文案统一为“15分钟内”、“15–30分钟”、“30–60分钟”，附带“预估圈层，非单点精确时间”说明；
   - 点击清单中的任意地点：
     - 清单卡片呈现绿色激活高亮；
     - 底部出现包含所选地点名称与说明的信息栏（无工程占位词汇）；
     - 地图上对应的标记放大高亮，接口完全对齐。
